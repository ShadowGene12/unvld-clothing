## 2024-05-18 - Module-Level Extraction of Expensive Array Operations on Static Data
**Learning:** In React functional components, deriving filter options or other unique lists from static mock data using O(N) array methods like `.map()`, `.flatMap()`, and `new Set()` inside the component body is an anti-pattern. This causes these expensive operations to run on every single re-render, which happens frequently when UI state (like dropdowns opening or filters changing) updates. Since the underlying mock data (`products`) doesn't change during runtime, calculating these inside the component is a pure waste of CPU cycles.
**Action:** Always extract expensive static data derivations (like creating unique categories/sizes lists from imported mock data) to the module scope, outside the React component. This ensures the calculation only happens once when the module is first evaluated, significantly improving re-render performance for complex pages like the Shop view.
