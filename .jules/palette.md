## 2024-10-24 - Dropdown Navigation Keyboard Accessibility
**Learning:** Found a common pattern in the Header where custom navigation dropdowns rely entirely on `onMouseEnter` / `onMouseLeave` (hover) events, making them completely inaccessible to keyboard-only and screen reader users. Simply tabbing to the button wouldn't open the menu.
**Action:** Implemented a reusable ARIA Disclosure pattern for hover-based menus. This includes adding an explicit `onClick={() => setOpen(prev => !prev)}` trigger, an `onFocus` handler to open the menu on Tab, and a robust `onBlur` handler using `e.currentTarget.contains(e.relatedTarget)` to close the menu when focus leaves the component. Also added necessary ARIA attributes (`aria-expanded`, `aria-haspopup`, `aria-controls`) and standard `focus-visible:ring-2` focus outlines to ensure interaction is discoverable and functional.
