## 2024-10-08 - Adding Keyboard Accessibility to Custom Hover Components
**Learning:** When adding accessibility to custom hover-based components like dropdown menus that previously relied solely on mouse events (`onMouseEnter`/`onMouseLeave`), it is critical to implement a complete set of alternative interaction paths for keyboard and screen reader users. Simply adding an `aria-expanded` tag is not enough. You must add an `onClick` toggle, an `onFocus` handler (to open on keyboard Tab), and an `onBlur` handler (checking `e.currentTarget.contains(e.relatedTarget)` to close when focus completely leaves the container).
**Action:** When auditing hover-based UI elements, always check for the accompanying keyboard focus equivalents (`onFocus`/`onBlur`) and ensure explicit `focus-visible` styles and standard ARIA attributes (`aria-expanded`, `aria-haspopup`, `aria-controls`) are present to maintain a 1:1 parity between mouse and keyboard experiences.
