## 2024-03-22 - Keyboard accessibility for hover-based dropdowns
**Learning:** Adding accessibility to custom hover-based components (like the `onMouseEnter`/`onMouseLeave` dropdowns in `Header.tsx`) requires careful toggling logic for keyboard navigation. I found that I need to add an `onClick` toggle using a functional update, apply explicit `focus-visible` styles so tab focus is visible, and use `onBlur` (checking `!e.currentTarget.contains(e.relatedTarget)`) to correctly determine when focus has moved completely out of the dropdown structure to close it.
**Action:** Whenever I encounter a hover-only interaction in this app's design system, I will implement parallel keyboard-accessible controls (onClick toggles, focus styles, onBlur container checks, and proper ARIA states like `aria-expanded` and `aria-controls`) to ensure the interaction is accessible without relying solely on a mouse.
